## Analysis & Presentation

- [x] **Establishing baselines** You DO actually need to check how accurate you would get just fitting the data with least squares or some other simple parametric method. You can do this via an MSE on the data given the model (likelihood of the data). **Done** -- `smi/analysis/baseline_fit.py`, report at `report/baseline.typ`. Likelihood and MSE turn out to be the same computation under Gaussian residuals, so the closed-form fit is both the simple and the rigorous option. Baseline (N=200): displacement RMSE 0.433 um free space / 0.462 um fiber, velocity RMSE 0.488 / 0.550 **um/ms** (these were recorded as 488 / 550 um/s before the units convention was settled; the artifact must be regenerated to carry the new key names). This is now directly comparable to a training log with no conversion, which was the point of the units work above. But the forward-model residual says the Michelson model explains only 9-38% of the variance *with displacement known*, so the baseline's error is model/data mismatch rather than a weak estimator -- the same decoder handles synthetic Michelson fringes ~20x better. Follow-up below.
    - [ ] **Why does the Michelson model fit this data so badly?** **Largely answered: it was the estimator, not the model.** `forward_model_residual` fit one amplitude/phase/offset across all 16384 samples (33.6 ms), which no single phase can do when a shot drifts 1-2.7 fringes within the record. Refitting per window of W=1024 samples and pooling the variances lifts the large-excursion cohort (N=1000, top 200 by excursion, live `k`) from R^2 0.013-0.063 to 0.272-0.781. `windowed_forward_model_residual` and its mandatory `scrambled_theta_control` are committed, and the artifact now reports global, windowed and control side by side per channel.
        - **W=1024 is chosen by the control, not by taste.** The scrambled-theta control (same window count, same 3 parameters, theta from a different shot) rises with shorter windows as pure fitting capacity: 0.006-0.009 at W=16384, 0.185-0.274 at W=1024, 0.569-0.681 at W=256. W=1024 maximizes the real-vs-control gap (up to 0.543); W=256's numbers must never be quoted as model agreement. Measured controls at W=1024 run about 2x higher than the spec that commissioned this work predicted (0.088-0.117) -- the windowed-vs-control *gap* and the choice of W both hold, but the absolute control figure in that spec does not reproduce, and no variant of the pairing (neighbour, small-excursion, random, time-reversed) gets near it. A 1024-sample window sweeps a median 2.17 fringes, so a 3-parameter fit against any oscillation of comparable rate captures ~0.2 by arithmetic; a white-noise control matches the theoretical `3/W` exactly (0.0028 vs 0.0029), which is what rules out an implementation error.
        - **Report per channel, never averaged.** Free-space 515 nm is the one case where W=1024 does not establish agreement: real 0.272 against a control of 0.185, a gap of just 0.087. Averaging the three channels would report 0.400 for that acquisition and hide it completely.
        - Still open: the residual amplitude dependence, and the coil-driver gain error Phase 3 measures. Bandwidth was informally ruled out (max fringe rate ~7.4 kHz, well inside band) but that check is not committed.
